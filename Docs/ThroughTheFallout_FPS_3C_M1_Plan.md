# ThroughTheFallout - FPS 3C 系统实施需求与设计规范（Milestone 1：基础 3C 骨架）

> **文档性质**：系统需求说明书与设计规范（PRD / Design Specs）  
> **面向对象**：负责技术方案选型与具体代码/资产落地的 AI Implementation Agent  
> **设计原则**：**定义“体验目标”、“设计哲学”与“验收标准”，技术实现方案（架构拆分、代码编写、变量命名、参数数值）全权交由实施 Agent 决策。**

---

## 一、项目背景与核心定位

1. **项目上下文**：
   * 本项目运行于 Unreal Engine 5，底层已搭建自研的 `GastroFramework` 插件（已封装 Gameplay Ability System、Enhanced Input 以及 PlayerState 持有 ASC 的架构）。
   * 项目目前已有第三人称原型，本次任务是在保留现有系统兼容性的前提下，开启一套独立的第一人称射击（FPS）3C 系统。

2. **手感核心定位：偏爽快的现代射击（Snappy / Responsive）**：
   * 目标对标类似《Apex Legends》、《Titanfall》或现代《使命召唤》的操作手感。
   * 体验核心关键词：**跟手、即时响应、无滑步、跑跳干脆、下蹲平滑**。绝不做沉重、拖泥带水的写实模拟手感。

---

## 二、既有工程约束与红线（Non-negotiables）

1. **框架架构约束**：
   * 必须兼容 `GastroFramework` 体系：角色的 Ability System Component（ASC）由 `PlayerState` 持有管理，输入映射需与框架的输入组件接轨，为后续技能打通铺路。
   * **严禁破坏或修改**现有的第三人称原型资产（如 `BP_TTFThirdPerson*` 相关蓝图与资产）。
2. **目录规范约束**：
   * 所有新增的逻辑蓝图、关卡与配置必须存放在 `Content/ThroughTheFallout/` 对应子目录下。
   * 所有美术模型、动画、白盒资产必须统一收拢在 `Content/Assets/` 下。
3. **技术自主权**：
   * **实施 Agent 拥有完全的技术自主权**：由实施 Agent 自行决定 C++ 与蓝图的职责划分边界、具体的类继承关系、函数接口设计、组件命名规范以及参数的最终调优数值。

## 三、体验目标与元思考设计规范（The "Why" Behind the 3C）

实施 Agent 在制定技术方案时，必须严格贯彻以下感知维度的设计目标：

### 1. Control（控制与视角层）
* **视线的神圣领域（零延迟与线性响应）**：
  * 人类转动眼球是没有加速度的。第一人称视角就是玩家的眼睛，视角旋转必须绝对跟手，杜绝任何黏滞、滤波或鼠标平滑感。
* **视角范围死限（Pitch Clamping）**：
  * 玩家快速向上或向下甩镜头时，必须在底层被严格截断在合理的人类颈部极限范围内，严防发生 90° 垂直视角的万向节翻转（Gimbal Flip）和画面穿模。
* **准星决定身位**：
  * 准星朝向即身体朝向，前后左右的移动逻辑必须以当前摄像机的水平视角为基准（向准星冲刺、向后倒退射击、左右横拉枪线）。

### 2. Character（移动物理与身法感知）
* **方波级移动启停（消除冰面滑步感）**：
  * **元思考**：爽快射击的核心对决体验依赖掩体边缘的晃身探头射击（ADAD Strafing / Jiggle Peeking）。
  * 角色起步必须迅猛，松开移动键时必须在极短距离内瞬间刹停。加减速度曲线应尽可能接近方波，绝不能让玩家感觉到像在冰面上溜冰般的惯性滑行。
* **坚实重力与空中自主权（力量感 + 变相规避）**：
  * **元思考**：游戏世界的跳跃如果使用纯现实重力，视觉上会表现得极度缓慢浮空（“月球漫步感”）。
  * 跳跃需要较快的上升与下坠加速度来营造力量感；但下坠变快会导致起跳轨迹焊死成为活靶子。
  * 因此必须赋予玩家**充沛的空中控制权（Air Control）**，允许在起跳后利用方向键微调空中落点与身位变向。
* **下蹲的“逻辑碰撞”与“视觉感官”解耦**：
  * **元思考**：按下蹲键时，从竞技对抗与受击掩体判定来看，物理胶囊体的尺寸必须迅速甚至即时收缩，防止玩家躲进掩体却依然被爆头；
  * 但如果摄像机视角也在同一瞬间硬切下落，屏幕画面会发生剧烈撕裂和瞬移，极易引发 3D 眩晕。
  * **设计要求**：物理层与视觉层必须分工处理——碰撞尺寸响应机制与相机眼高的平滑过渡必须在感官上实现丝滑缓冲。同时必须保留低矮障碍物下的防强制起身检测。

### 3. Camera & View（双视图与构图分离）
* **1P / 3P 双网格体分离原则**：
  * **元思考**：第一人称画面的手臂和武器是服务于屏幕构图的（必须在视角前方呈现最佳姿势），而第三人称模型是服务于世界空间物理运动的。
  * 必须实现第一人称视图（仅自己可见、贴近视口渲染）与第三人称视图（自己不可见、对外部可见、保留地面影子投射）的正确分离与投影配置。
